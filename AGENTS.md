# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

GH Review (`gh-review-desktop`) is a native Rust + egui (eframe 0.37) desktop app for reviewing GitHub pull requests. See `README.md` for features and `docs/superpowers/specs/2026-10-19-gh-review-desktop-design.md` for the full spec. Code comments cite spec sections (e.g. "spec §8.4"), so look there for intent.

## Commands

CI (`.github/workflows/ci.yml`) runs these on Linux, macOS and Windows; all must pass:

```sh
cargo fmt --check
cargo clippy --workspace --all-targets --features ai-testing -- -D warnings
cargo test --workspace --features ai-testing
cargo test --release -- --ignored          # perf guardrail (tests/perf_large_pr.rs), Linux CI only
```

Other useful ones:

```sh
cargo run                                  # on macOS goes through scripts/macos-run.sh (re-sign + dev .app bundle)
cargo test --lib state::pr_detail          # unit tests in one module
cargo test --test contract_threads         # one integration test file
cargo test --lib shots -- --ignored        # offscreen screenshots → target/ui-shots/ (needs a GPU)
cargo clippy --workspace --all-targets --features ai-testing,local-classifier -- -D warnings   # also compile the on-device classifier (macOS)
```

Linux builds need `pkg-config libdbus-1-dev libxkbcommon-dev libgtk-3-dev`.

macOS release: `scripts/macos/archive.sh` then `scripts/macos/notarize.sh` (outputs in `target/dist/`; setup in `scripts/macos/README.md`). `.cargo/config.toml` sets `scripts/macos-run.sh` as the macOS cargo runner — it re-signs the debug binary so the keychain's "Always Allow" survives rebuilds, and wraps it in `target/bundle/` via `scripts/macos/dev-app.sh`.

## Architecture

The crate is a library (`src/lib.rs`) plus a thin `src/main.rs` that calls `app::run()`, so integration tests can use the public module tree.

**UI ⇄ network split (`src/runtime.rs`).** The GUI thread never does I/O. The UI sends a `Command` to a `Worker` (its own multi-thread tokio runtime); results come back as `Event`s that `ReviewApp` drains once per frame. Adding a network feature usually means: a `Command` variant + handler in `runtime.rs`, an `Event` variant, a client method in `src/github/`, and handling in `app.rs` / `state/`.

**Stale-event rule.** Each opened PR gets a `SessionId`; every PR-scoped `Event` carries it, and events for a PR the user has left are dropped. Preserve this when adding PR-scoped commands/events.

**`src/app.rs` (`ReviewApp`)** owns screen routing (`ScreenKind`, `route`), global shortcut/menu/palette dispatch (action ids from `ui/command.rs` registry), settings/theme, and applies the action enums widgets return.

**State vs. UI.** `src/state/` holds screen state and reducers, kept pure and unit-tested; `state/pr_detail.rs` (`PrSession`) is the largest — it drives PR loading as a state machine (metadata first so the head SHA is known, then files page by page), optimistic comment posting, pending review, viewed marks. Widgets in `src/ui/widgets/` and screens in `src/ui/screens/` don't mutate app state directly: they return action enums (e.g. `PrDetailAction`, `DiffAction`) that `app.rs` applies. Widget decision logic is factored into pure functions so it's testable without a window.

**Diff pipeline (`src/diff/`).** `parse` (patch → hunks) → `anchor`/`annotate` (map review threads/comments to rows) → `row_model` (flattened rows with offsets for virtualization) → `ui/widgets/diff_view.rs` renders only visible rows through a bounded `highlight` cache (syntect). `expand` handles context expansion; `image` handles image diffs. Performance on huge PRs (≥50k rows) is guarded by `tests/perf_large_pr.rs`.

**GitHub client (`src/github/`).** Hand-written over reqwest, REST + GraphQL (PR list is one GraphQL search). Reads may be retried; writes never are. `error.rs` classifies failures into `GhError`. Supports GitHub Enterprise Server via `Endpoints`.

**Persistence (`src/persist/`).** `settings.toml` plus per-PR `sessions/<host>/<owner>/<repo>/<number>.json` (viewed marks, pending review, composer drafts) with atomic, debounced writes. Tokens and LLM API keys live only in the OS keychain (`src/auth/store.rs`, service `gh-review-desktop`; LLM keys under the `llm:<provider>` account) — never in settings or session files.

**AI review (`src/ai/`, `#[cfg(unix)]`).** The engine: `llm.rs` builds provider clients from the vendored `crates/llm` (Anthropic + OpenAI behind neutral types); `crates/sandbox` (vendored) runs the agent's bash on a PTY inside an OS sandbox (Seatbelt / bubblewrap) that can't write `.git/` and has no credentials; `crates/approval` (`review-approval`, pure, no I/O: tree-sitter-bash parse → deny paths (default list includes `.git/config`, `.git/credentials`; a text match that stops naive reads; the sandbox's OS deny-read list is the guarantee; `.git/config` stays text-protected only because git itself must read it, so a search that recurses, or reaches hidden/ignored/untracked files (`grep -r`, `rg -u`/`--hidden`/`--no-ignore`, `git grep --untracked`/`--no-index`), and `cd` into a path through `.git`, are rules that ask rather than run; the sandbox denies reads of repo-local `.env*` files at any depth (Seatbelt: a regex rule, covers files created later; bubblewrap: `/dev/null` over the `.env*` files that exist at launch, found by a bounded walk that skips `.git`, `node_modules` and `target`, so later ones are not covered on Linux)) → rule policies (read-only, `git` read (never `git config`), repo-allowed, `mkdir` in cwd) → ask) classifies each command as `Run`/`Ask`/`Deny` and fails closed (any construct it can't account for asks, never runs; `Deny` is a tool error with no prompt). An optional model stage (`CommandClassifier`, off by default via `[ai.auto_approve].local_classifier`) sees only segments the rules could not vouch for, one per call, under a decision cache and a per-command timeout (one deadline per bash command, not per model call; a timed-out or already-busy classifier is skipped, never stacked); a never-approve filter means a model "safe" never silently runs a segment whose command is a listed binary (network, interpreters, shells, exec wrappers, script-capable editors/`awk`/`sed`/`tar`, installers, data-changing tools, shell-state builtins such as `alias`/`trap`/`hash`/`ulimit` that change later commands in the persistent shell, and tools that load and run repo config or plugins such as `eslint`/`tsc`/`terraform`/`pbcopy`), is a relative path (PR code) or a non-system absolute path, or has any argument word naming a listed binary (`flock … curl`, `awk 'BEGIN{system("curl")}'`), a working-tree path (`./x`, `dir/x`, `--opt=./x`, also as the target of a `<` stdin redirect, which must not hold shell syntax either) or an option that names a program to run (`--pre`, `--to-command`), a `!`/`+!` pager prompt word, or an assignment value that is a working-tree path, or a command name that is not ASCII (pagers/viewers `less more most man info` and `mkfs.*` are listed; an argument or assignment value containing shell syntax (``; & | ( ) ` $ < > \ ' " { }`` or a line break) is never model-approved; residual: a bare `evil.sh` operand with no `/`, or a plain argument an unlisted program shell-evaluates, is still approvable, so such programs must be listed), so the model can only flag or abstain on those, and, with parallel reviewers, a busy model makes the other reviewers' commands ask (fail-closed: the classifier never queues, and how many prompts that adds varies), and a missing, failing, timed-out or `Unavailable` classifier yields exactly the no-classifier verdict (fail-closed); the classifier implementation lives in `src/ai/local_classifier/` behind the `local-classifier` Cargo feature (off by default; internal `_classifier` gates the code, never enable it alone): `DecisionClassifier` asks a shiso decision model (`shiso-runtime`, registry name from `[ai.auto_approve].decision_model`, default `smollm2-135m-decision`) one approve/ask/deny question per segment (`decision.rs`; input `cwd:`/`task:`/`cmd:` with the command escaped to one line; `approve` at probability >= `approve_threshold` (0.60) is `Safe`, `deny` is `Dangerous`, anything else `NeedsApproval`); `schema.rs` loads the model's `decision_schema.json` or the built-in default (an invalid file is `Unavailable`, never replaced by the default); `loader.rs` drives `ClassifierState` (download, load, ready, switching models); `weights.rs` finds or pulls the model in the registry through `shiso_runtime::hub`; the open happens in `loader.rs` (`ShisoEngine::load` → `open_runtime`) with `Runtime::open(Source::Registry(..))`, so the `Runtime` holds the install lock for as long as the classifier lives, `max_num_seqs = 1`. Metal on macOS, built into the macOS release by `scripts/macos/archive.sh`; `local-classifier-cuda` adds CUDA on Linux and needs the CUDA toolkit with `SHISO_CUDA_COMPILE=1`, links cuBLAS and is untested; weights are downloaded only after the user turns the setting on, stored in `models/` under the config root, never bundled. It must fail closed by returning `Unavailable`; the device eval is `model_stage_real` in `tests/auto_approve_eval.rs` (`SHISO_TEST_DECISION_MODEL_DIR`); `tools/` are the agent tools, `agent.rs` the agent loop, `pipeline.rs` the scout → reviewers → challengers → verifiers → assembler orchestrator, `context.rs`/`checklist.rs` the repo context (`.github/REVIEW.md` `## Checks` → `repo:*` items, directory-scoped `AGENTS.md`/`CLAUDE.md`, skills index), `store.rs` the SQLite persistence (`ai.sqlite`), `checkout.rs` the app-run git checkout/restore and prepare commands, and `hub.rs` the worker-side hub that turns AI `Command`s into `Event`s like the rest of `runtime.rs`. The UI side is `state/ai_review.rs` plus `ui/widgets/ai_panel.rs` and `ai_dialogs.rs`, following the same action-enum and `SessionId` rules. AI setup lives where it is used, not in a Settings list: providers and models are edited in Settings' AI tab (`ui/widgets/settings_ai_tab.rs`, built-in model presets in `ai/presets.rs`), as is `[ai.auto_approve]` (its own dialog; Save sends `ClassifierSetEnabled` when the classifier is switched or its model changes while on, Retry sends `ClassifierDownload`); the repo↔folder link and a repo's commands/prepare/extra paths live in the PR's AI tab Local checkout row (`ai_panel.rs`, `ai_repo_dialog.rs`, link and start pre-check helpers in `ai/repo_link.rs`) and the PR list's Local repos tab (`state/local_repos.rs`, `ui/widgets/local_repos.rs`). The agent has no GitHub credentials and no write path: nothing reaches GitHub except the user's own review submit.

## Tests

- Unit tests live inline in each module. Shared helpers are in `src/test_support.rs` (`#[cfg(test)]`); read it before adding helpers and don't redefine existing ones. Load fixtures with `use crate::fixture; fixture!("name.json")` (compile-time embedded from `tests/fixtures/`).
- `tests/contract_*.rs` run `GithubClient` against `wiremock` and assert exact request bodies. Their shared helpers are in `tests/common/mod.rs` (integration tests can't see `test_support`).
- `src/ui/shots.rs` renders every screen with `egui_kittest` for comparison against the HTML mockups in `docs/design/mockups/`; missing glyphs fail the run.
- `.github/REVIEW.md` is this repo's own review checklist, consumed by the AI reviewer (`src/ai/context.rs` parses its `## Checks` bullets; `[glob]`-prefixed ones scope to matching paths). Keep it in sync when the rules above change; `context_parses_this_repos_review_md` guards it.
